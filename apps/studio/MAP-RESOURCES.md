# Browser-resolved BGT map plates

The same browser resource pattern as Commons, with native SVG bytes rather than JPEG. No heavy live geography in Git, no additional server or map renderer dependency. The native Postext layout and export stay unchanged.

A book contains `resources/live-maps/<id>.svg.json` (version 1, source pdok-bgt, bbox in CRS84 longitude/latitude, style water-first / figure-ground / network, points), and an equally sized, visibly marked local reserve SVG at the corresponding `.svg` path. Use the ordinary SVG resource in the manifest. The local fallback also allows static manifest validation and CLI layout tests; CLI never retrieves the live geography. A live browser intercepts only these paths. Two workers share geometry across variants. The loader follows next links only within the same PDOK collection, applies bounds, time and size caps, and rejects empty or non-polygon layers. The map uses a local latitude-adjusted equirectangular projection, clips to its extent, and includes an approximate scale bar and attribution. Roads are surface polygons, not navigable network edges. Bridge parts do not imply public access. Point labels are authored in native Markdown and must match the projection. Native exports should embed the resulting SVG; verify actual outputs offline.

Source: https://api.pdok.nl/kadaster/bgt/ogc/v1/collections?f=json (CC0). The metadata and collection names are verified. Live feature responses and CORS are not yet verified. On any failure, the existing local SVG is returned and clearly says LIVE BGT UNAVAILABLE. Reload/reopen the book to retry. Depending on Sandbox saved state, a fresh library import may be needed. The host loader has no general external URL support. No new manual Actions or native engine changes.
